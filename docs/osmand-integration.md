# OsmAnd integration

See [feasibility.md](feasibility.md) for the format research this is based on.

## What the package contains

`python -m app.cli build-osf` (or `GET /osmand/syria-maps.osf`) produces a ZIP:

```
items.json
res/syria_maps_icon.png        original artwork, generated by the builder
res/syria_maps_image.png
tracks/syria-maps-public-services.gpx
```

`items.json` (abridged; full example in [`osmand/items.example.json`](../osmand/items.example.json)):

| Item | Purpose |
|---|---|
| `PLUGIN` (`pluginId: syria.maps`) | Name/description in Arabic and English, icon and image (`@file` refs into `res/`) |
| `RESOURCES` (`file: res`) | Installs the icon/image into the plugin folder |
| `MAP_SOURCES` | One online tile source per layer with `osmand.map_source: true` |
| `FILE` (`subtype: gpx`) | Offline GPX waypoints of layers with `osmand.gpx_snapshot: true` |

The tile source uses `timesupported: true, expire: 60` so OsmAnd re-downloads cached tiles after
60 minutes — this is how server-side updates reach users without a new package.

## Building for your server

The tile URL is **baked into the package**, so build it with the public HTTPS URL of your API:

```bash
cd backend
python -m app.cli build-osf --base-url https://maps.example.org --output ../dist/syria-maps.osf
python -m app.cli validate-osf ../dist/syria-maps.osf
```

`--storage memory` builds from `database/fixtures` (no database needed); without it the GPX snapshot is
taken from PostGIS. The server endpoint `/osmand/syria-maps.osf` always uses `SYRIA_MAPS_PUBLIC_BASE_URL`.

## Installing on a phone

1. Install OsmAnd (Google Play).
2. Download `syria-maps.osf` and open it with OsmAnd (or *Menu → Settings → Import*).
3. Confirm the import. The plugin "Syria Maps / خرائط سوريا" should appear under *Plugins*.
4. Enable the official **Online maps** plugin.
5. *Configure map → Overlay map* → `Syria Maps - Public services (synthetic)`; adjust transparency.
6. *My places → Tracks* → `syria-maps-public-services` → show on map (works offline).

Alternative without `.osf`: open the URL returned by `GET /osmand/add-tile-source/public-services`
on the phone (OsmAnd's documented `osmand.net/add-tile-source` link format).

For local testing from the Android emulator use `--base-url http://10.0.2.2:8000`; the validator
accepts it with a warning. Release packages must use HTTPS.

### On-device checklist (please report results in an issue)

- [ ] OsmAnd version and Android version: …
- [ ] Import dialog lists: plugin, map source, track
- [ ] Plugin appears under Plugins with Arabic name when the phone language is Arabic
- [ ] Overlay shows coloured dots near the synthetic clusters (e.g. zoom 14 around 33.45 N, 36.20 E)
- [ ] After changing data on the server, tiles update after ≤ 60 min (or after clearing tile cache)
- [ ] GPX visible offline (airplane mode)

## Known limitations

- Overlay tiles need connectivity (OsmAnd caches tiles already viewed).
- The GPX snapshot is static; import a new package (or the `/download?format=gpx` file) for updates.
- `POI_UI_FILTERS`, `DOWNLOADS` and `SUGGESTED_DOWNLOADS` are not used yet because some of their
  values (OsmAnd POI category keys, `DownloadActivityType` names) were not verified in the source.
- Any feature requiring code inside OsmAnd would need a separate Android companion app using the
  OsmAnd AIDL API; none exists in this repository.
